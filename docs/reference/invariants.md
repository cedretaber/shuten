# 不変条件と対象外

仕様書（`docs/spec/mvp-spec.md`）で確定している設計上の制約を、実装時に参照しやすい形に抜き出したもの。
正本は仕様書であり、食い違いがあれば仕様書が優先する。
これらは実装の都合で崩してはならない。変更が必要だと考えた場合は、コードを変えるのではなく、
まず仕様書の改訂を提案する。

## 本文の扱い

- 保存本文はファイル先頭の BOM を除外する以外、一切加工しない。
  Unicode 正規化、空白除去、改行の統一を暗黙に行わない。CRLF はそのまま保持する。
- 位置は BOM 除外後の保存本文上の **UTF-16 コード単位** で表し、範囲は `[start, end)` とする。
  フロントエンドとバックエンドで同じ換算を使う。
- 文字数（分割長・文脈長）は **書記素クラスタ数** で数える。位置の単位とは別物として扱う。
- 段落は CRLF・LF・CR のいずれか 1 つで区切られた行。CRLF は 1 つの区切り。
  空行も段落として保持し、区切りの改行列は直前の段落範囲に含める。
- サロゲートペア、異体字セレクタ、結合文字、絵文字の連結、CRLF の途中で分割しない。
- 本文とモデル出力は HTML として実行せず、テキストとして表示する。

## 指摘の位置

- 文字位置はアプリが原文から確定する。LLM が返した数値位置は信用しない。
- 引用は **完全一致** でのみ位置を確定する。近似一致による位置の自動割り当てはしない。
- 完全一致に失敗した候補は「位置特定失敗」として保存し、一覧に表示する。
  診断用の類似候補（改行統一・NFC 比較に限定）は記録するだけで、
  強調表示・再確認・採用位置には使わない。
- 引用の開始位置が検査対象内にある候補だけを採用する。
  参考文脈内から始まる候補は担当範囲へ付け替えず、診断記録に残す。
- 引用だけで位置が一意に決まる場合は、前後の引用の不備だけを理由に位置特定失敗にしない。

## 検査処理

- 処理順序は「分割 → 観点別検査 → 引用・位置検証 → 重複統合・許容語後処理 → 再確認 → 結果表示」。
- 観点（誤字・脱字／日本語の自然さ）ごとに別々の要求を送り、要求間で会話履歴を共有しない。
- LLM 生成要求はバックエンド全体で **単一キュー、同時実行数 1**。UI の設定項目にしない。
- 再確認は「維持」「撤回」「作者への確認事項」のいずれかを返し、修正案を改訂しない。
  追加の再確認ループは行わない。
- 再確認の結果は作者の採否を上書きしない。初回判定は履歴に保持する。
- 重複統合は同一の検査実行内に限る。別実行（別モデル・別設定・同条件の再実行）の候補、再確認結果、採否を混ぜない。
- 許容語による自動抑制は「位置確定済みの表記訂正で、引用内の登録語の出現 1 箇所を別の文字列に
  置き換えるだけで修正案を再現できる」場合に限る。登録語内の部分訂正（リュシア→ルシア）は対象、
  登録語の外側に及ぶ変更・削除・複数箇所は対象外。抑制候補は削除せず、非表示にして再閲覧できるようにする。
- 失敗・形式不正を正常な空配列（指摘ゼロ）に置き換えない。
  `finish_reason == "length"` は出力打ち切りであり、JSON が解析できても成功扱いしない。
- 入力上限超過時は本文を黙って切り捨てず、エラーとして設定変更を案内する。
- 本文はデータとして区切り、本文中の命令文に従わない指示をプロンプトに入れる。

## LM Studio 接続

- 未ロードのモデルに生成要求を送らない。接続確認では先に `GET /api/v0/models` で `state` を確認し、
  `not-loaded` ならユーザーに LM Studio 側でのロードを案内する（JIT ロードが VRAM 溢れを起こし得る）。
- `AbortController` による中断は HTTP 通信の中断であり、生成終了の確認ではない。
  停止・タイムアウトでは中断後も生成終了を未確認として扱う。
- 生成終了を確認できない場合は「復旧待ち」にして自動送信を止め、手動再開を待つ。
  時間経過を終了の証拠とみなさない。
- 思考モデルの `max_tokens` は思考分を含めて予算配分する。

## 実行管理

- 「再開」は既存の実行 ID の続き。「新規検査の開始」は原稿版・設定が同じでも常に新しい実行 ID。
  同条件の再実行を既存実行の再開に置き換えない。二重送信の防止は要求の同一性で判定し、条件の一致では判定しない。
- 「完了」「一部失敗」「停止中」「実行中」を区別する。未処理範囲がある状態を「問題なし」と表示しない。
- 分割範囲と確定位置の正本はサーバーが保存した UTF-16 範囲。ブラウザは表示に使うだけで再計算結果で上書きしない。
  再開時も保存済み範囲を使う。`Intl.Segmenter` の結果は実装依存であり、両側で一致すると仮定しない。
- SSE は通知手段。状態の正本は DB。ブラウザ切断で検査は止めず、再接続時は API で状態を取得して復元する。
- DB トランザクションに LLM 応答待ちを含めない。

## 採否と本文

- 「採用予定」「却下」「保留」は評価の記録であり、本文への修正適用ではない。
  MVP では本文を書き換える機能を一切作らない。

## セキュリティ・プライバシー

- 原稿と検査結果はローカルに保存し、外部サービスへ送信しない。
- Web アプリは初期設定でループバックアドレスのみで待ち受ける。
- API キーを検査履歴・ログ・結果出力に含めない。

## 対象外（作らない）

仕様書 3.2 節のとおり。特に以下は「あると便利」に見えても MVP では実装しない。

- 本文への修正適用、手動編集、diff 表示、取り消し・やり直し
- 近似一致による位置の自動割り当て
- 設定・時系列・人物などの整合性検査、推敲提案
- RAG、複数モデル、ファインチューニング
- Word・PDF 読み込み、ルビ記法の専用解析
- クラウド公開、複数ユーザー
